# Rules (Regras) do Projeto HelpDeskMVC

## O que são Rules?

Rules são regras e padrões definidos para manter o projeto organizado.

Essas regras ajudam:
- manter padrão de código
- evitar bagunça
- facilitar manutenção
- melhorar aprendizado
- trabalhar de forma parecida com equipes reais

---

## Por que usar Rules?

Sem regras:
- cada aluno faz de um jeito
- o projeto fica desorganizado
- o código fica difícil de entender

Com regras:
- todos seguem o mesmo padrão
- o projeto fica mais profissional
- o aprendizado melhora

---

# Rules Oficiais — HelpDeskMVC

## 1. Sempre entender antes de copiar

Nunca copiar código sem entender.

Todo aluno deve:
- ler
- testar
- entender
- conseguir explicar o código

---

## 2. Não pedir projeto inteiro para IA

Sempre dividir funcionalidades em pequenas partes.

Exemplo correto:

- criar Model
- criar Controller
- criar View
- criar formulário
- criar validação

---

## 3. Manter padrão MVC

Cada responsabilidade deve ficar no lugar correto.

### Models
Responsáveis pelos dados.

### Controllers
Responsáveis pelas ações e fluxo.

### Views
Responsáveis pela interface.

---

## 4. Não misturar HTML dentro do Controller

Controller NÃO deve conter HTML.

HTML deve ficar apenas nas Views.

---

## 5. Nomear arquivos corretamente

Usar nomes claros e organizados.

Exemplos:

- Chamado.cs
- ChamadosController.cs
- Create.cshtml
- Index.cshtml

---

## 6. Não duplicar código

Evitar copiar o mesmo código várias vezes.

Sempre tentar reutilizar.

---

## 7. Manter o projeto organizado

Pastas devem seguir padrão:

- Controllers
- Models
- Views
- wwwroot

Futuro:
- Data
- ViewModels

---

## 8. Sempre testar antes de finalizar

Antes de considerar pronto:

- executar projeto
- testar navegação
- testar formulário
- verificar erros

---

## 9. Comentários apenas quando necessário

Não comentar código óbvio.

Comentários devem explicar:
- regras importantes
- decisões importantes
- comportamentos complexos

---

## 10. Erros fazem parte do desenvolvimento

Errar é normal.

Programação envolve:
- testar
- corrigir
- melhorar
- aprender continuamente

---

# Como usar IA corretamente

## A IA deve ajudar no aprendizado

A IA deve:
- explicar
- sugerir
- ajudar a corrigir
- ajudar a organizar

A IA NÃO deve:
- substituir o aprendizado
- fazer tudo sem entendimento

---

# Regra final do projeto

## Código simples > código complexo

Prioridade do projeto:
- clareza
- organização
- entendimento
- aprendizado

Não é necessário criar sistemas complexos para aprender bem.
